# CAN Bus Analyzer

![Version](https://img.shields.io/badge/version-1.0.0-blue.svg)
![Go](https://img.shields.io/badge/Go-1.21+-00ADD8.svg)
![JavaScript](https://img.shields.io/badge/JavaScript-ES6+-F7DF1E.svg)
![License](https://img.shields.io/badge/license-MIT-green.svg)

**CAN Bus Analyzer** — это веб-приложение для анализа данных CAN шины в реальном времени с поддержкой UDS протокола, фильтрации сообщений и интерактивной визуализации данных.

## ✨ Основные возможности

- **Режимы работы**: Чтение данных из реальной CAN шины или эмуляция через файл логов
- **Фильтрация сообщений**: Динамическая фильтрация по CAN ID с сохранением в базе данных
- **Модульная визуализация**: Настраиваемые виджеты с различными типами графиков
- **Отправка команд**: Возможность отправки CAN фреймов и UDS команд обратно в шину
- **Логирование**: Полное логирование всех полученных и отправленных сообщений
- **Адаптивный интерфейс**: Современный веб-интерфейс, работающий на любых устройствах

## 🚀 Быстрый старт

### Предварительные требования
- Go 1.21 или выше
- SQLite3
- Современный веб-браузер
- Доступ к CAN шине (опционально, для режима работы с реальной шиной)

### Установка и запуск

1. **Клонирование репозитория**
   ```bash
   git clone https://github.com/playaer/analyzer.git
   cd analyzer
Установка зависимостей

bash
go mod download
Настройка CAN интерфейса (только для режима реальной шины)

bash
sudo ip link set can0 type can bitrate 500000
sudo ip link set up can0
Запуск приложения

bash
# Режим реальной CAN шины (требует прав sudo)
sudo ./can-analyzer -mode=can

# Режим чтения из файла
./can-analyzer -mode=file -file=rule.txt

# С отключенным логированием
./can-analyzer -mode=can -log=false
Открытие в браузере

text
http://localhost:8080
📋 Доступные аргументы командной строки
Аргумент	По умолчанию	Описание
-mode	can	Режим работы: can (реальная шина) или file (чтение из файла)
-file		Путь к файлу для чтения (только в режиме file)
-log	true	Включить логирование CAN сообщений
-can_interface	can0	Имя CAN интерфейса (режим can)
-baud_rate	500000	Скорость передачи данных CAN (бит/сек)
🎛️ Использование веб-интерфейса
1. Отправка CAN фреймов
CAN ID: Введите идентификатор в формате 0x200 (шестнадцатеричный)

Данные: Введите байты данных через пробел, например: 01 02 03 04

Отправка: Нажмите "Send CAN Frame" для отправки фрейма

2. Управление фильтрами
Добавление: Введите CAN ID и нажмите "Add Filter"

Отображение: Все активные фильтры отображаются в блоке фильтров

Удаление: Нажмите "×" рядом с фильтром для его удаления

Фильтрация: При активных фильтрах только сообщения с указанными CAN ID будут обрабатываться

3. Настройка виджетов
Добавление виджета: Нажмите "Add Widget" в блоке виджетов

Виджеты можно растягивать по горизонтали в 2 или 3 раза

Реализовано через правый нижний угол виджета

Привязка к текущей сетке (350px - минимальная ширина)

2. Перетаскивание виджетов:
Виджеты можно перетаскивать внутри контейнера

Привязка к сетке при отпускании

Сохранение порядка виджетов между сессиями

3. Расширенная конфигурация canChart2:
Пользовательское название виджета
До 4 параметров на одном графике

Для каждого параметра:
Название
CAN ID
Номер байта (0-7)
Размер данных (8, 8u, 16, 16u, 32, 32u, 32f)
Цвет линии
Границы графика по Y (или авто)

Компонент параметра вынесен в отдельный файл

4. Модульная архитектура:
ParamConfig - компонент конфигурации параметра
WidgetDrag - перетаскивание виджетов
WidgetResize - изменение размера
WidgetService - общие сервисные функции

Все изменения совместимы с текущей структурой проекта. Для реализации перетаскивания используется нативный drag & drop, а не сторонние библиотеки.

💾 Система фильтров
Особенности реализации
Сохранение в БД: Все фильтры сохраняются в SQLite базе данных

Динамическое применение: Фильтры применяются в реальном времени

Веб-интерфейс: Интуитивное управление через веб-интерфейс

Счетчики сообщений: Отслеживание количества обработанных сообщений для каждого фильтра

API фильтров
GET /api/filters - получение списка всех фильтров

POST /api/filters - добавление нового фильтра

DELETE /api/filters?can_id=0x200 - удаление фильтра по CAN ID

📊 Форматы данных
Входной формат файла логов
text
11:15:53.794 1 0x508 STD Rx 8 00 00 00 00 00 00 00 00
11:15:53.804 1 0x274 STD Rx 8 00 00 55 AA 55 AA 55 AA
Поля: время, номер шины, CAN ID, тип, направление, DLC, данные

Формат WebSocket сообщений
json
{
  "type": "can_frame",
  "id": "0x200",
  "data": "0102030405060708",
  "dlc": 8,
  "time": "2025-01-01T12:00:00Z"
}
Формат конфигурации виджета
json
{
  "widgetId": "widget-abc123",
  "canId": "0x200",
  "type": "canChart2",
  "config": {
    "dataSource1": "0-1",
    "dataSource2": "2-3U",
    "color1": "#ff6384",
    "color2": "#36a2eb"
  }
}
🔌 WebSocket API
Входящие сообщения (от сервера)
can_frame: Сообщение CAN шины для обработки

ack: Подтверждение отправки CAN фрейма

Исходящие сообщения (от клиента)
send_can: Запрос на отправку CAN фрейма

uds_command: Команда UDS протокола (в разработке)
